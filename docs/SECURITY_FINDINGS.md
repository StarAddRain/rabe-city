# 原文算法的安全问题与测试边界

## 1. 无认证私钥的发送方伪造（实测可复现）

原文令 `X1 = B_i A_i^(H·τ − q_i)`，`X3 = g^τ`。但没有证明 X3 的生成者知道 τ，也没有把 X3 纳入不可修改的签名挑战。

攻击者针对拥有所需属性的已注册身份 i，只使用公开参数、公钥 Q_i 和聚合辅助项：

1. 正常构造 C1～C4，计算 `H = H(C1||C2||C3...)`。
2. 选择 τ，令 `X1 = B_i A_i^(H·τ)`。
3. 令 `X3 = g^τ · Q_i^(H⁻¹)`，其余 X 分量取该身份对应的公开值。

当 `H != 0` 时，验证中的配对增加项为：

`e(A_i^H, Q_i^(H⁻¹)) = e(A_i,Q_i)`。

这个项恰好抵消原验证等式中缺少 `−q_i` 引起的差异。于是攻击者不知道 q_i，仍能冒充 i 通过验证，并使接收车辆恢复攻击者选择的消息。

`Benchmark` 末尾明确用 `BigInteger.ZERO` 而非合法 q_i 生成 X1，然后仅使用公开 Q_i 修改 X3。日志中 `sender_authentication_forgery_accepted=true` 就表示此攻击成功。H=0 为极低概率边界，攻击者可重选随机量；当前测试遇到该边界会终止而非掩盖结果。

因此，“双方合法时通过率 100%”只说明正向功能正确，不能证明该机制认证了真实发送方。正常非法属性组合被拒绝，也不能排除此冒充攻击。

## 2. C4 缺少完整性保护（实测可复现）

原文的 H 仅覆盖 C1、C2 和 C3。将 C4 替换成 `C4·g`，发送方验证仍可通过，但 D4 会多出 `e(g,A_receiver)`，破坏恢复结果。

日志 `C4_tamper_passes_sender_verification=true` 表示该问题存在。可选 Hybrid 封装会因恢复的会话密钥错误而拒绝 AES-GCM 标签，但它不修复第 1 项身份伪造。

## 3. 撤销范围必须明确

- `Update` 改变指定密文 C4，RI 必须与该密文、其更新版本一致；不能把某一密文的 RI 更新直接用于所有历史密文。
- 多轮目标不同的更新，需要累积相应密文的 RI；本次每轮对同一密文依次撤销 20 辆车并检查全部 100 辆车。
- `Deregister` 更新 T̂/Q̂ 不会自动改变已存在的 C4 或 X 组件。新公钥的效果直接作用于之后生成的密文。
- 已取得的旧密文 + 旧 hdk + 旧 sk 仍可恢复旧消息。程序把这个边界作为预期成功测试记录，避免隐瞒。
- 原文没有定义跨 VCS/KC 的更新事务、身份鉴别通道和防重放序号，本实现也不把这些未定义机制算作已验证。

## 4. 后续修订建议

应先修订协议并给出证明，再实现安全版本。发送方认证需要能够证明认证密钥持有、绑定发送方身份及不可变密文/策略字段的签名或知识证明。C4 是授权更新字段，其完整性还要与可验证更新记录及版本绑定。简单扩大当前 H 的字段范围，不足以自动修复第 1 项可塑性。不能在保持原公式不变的同时声称已经消除这些攻击。

## 5. 本次四端分层注册版

以上第 1–4 节保留自用户提供的版本，提及的旧 Benchmark 是历史验证，不是本次重新执行的完整压力测试。当前版本扩大了发送挑战绑定字段并增加了节点权限、版本检查和原子持久化，但没有修复第 1 节的代数伪造。分层注册不应被表述为已经获得原论文整个方案的安全证明。当前测试范围见 TEST_REPORT.md，构造适配见 REGISTRATION.md。
