# 第 6 节的对应关系与工程扩展

参考用户提供的 Hohenberger 等《Registered Attribute-Based Encryption》（2023），第 6 节 Construction 6.1（PDF 第 45–46 页附近）。该节是将 slotted registered ABE 编译成 registered ABE 的通用方法，不包含车辆角色、双向验证、注销或云端解密接口。

## 核心注册结构

| 第 6 节 | 代码 / 状态 |
|---|---|
| `L=2^ell` | Curator.capacity；配置容量向上取 2 的幂 |
| `crs_k`，槽位数 `2^k` | `Curator.boot`，每层独立生成 Scheme，持久化 public CRS 与 cross terms |
| `ctr` | `registry-state.json` 中单调增加的 ctr，初始 0 |
| `KeyGen(crs,aux)` | A/C `Client.work`，每层在 `ctr mod 2^k` 槽位独立 KeyGen；私钥写本机后才上传公钥 |
| `IsValid` | `Scheme.isValid`，验证公钥及 V/R 交叉项；不是仅在界面添加车辆 |
| `D1[k,j]` | 当前层槽位的公钥、属性、全局身份；即使该层尚未填满，也写入新槽位 |
| 满层时 `Aggregate` | `Curator.submit`，只在当前槽位是该层最后一个槽位时执行 `Scheme.register` |
| `D2[i,k]` / hdk | 全局身份、层号指向已完成块的辅助项快照；每个快照包含该块各槽位辅助项 |
| `mpk=(ctr,mpk_0,...,mpk_ell)` | `/view` 中 ctr/latest 和 `/block` 对应的注册块 |
| `Encrypt` | `Client.api(/send)` 对所有非空 latest 层分别加密同一个 GT 会话消息，再 AES-GCM 封装文字 |
| `Update` / `GetUpdate` | `/node/update` 查 D2；按不可变块 ID 下载并缓存相应辅助项，重启可重新下载 |
| `Decrypt` | `Compiler6.level(ctr_ct, ctr_sk)`，选择 `MSB(ctr_ct XOR ctr_sk)` 对应层；B 转换，C 用对应层本机 r 完成解密 |

论文槽位从 1 开始，Java 数组从 0 开始；代码 `ctr % size` 对应论文 `(ctr mod size)+1`。界面身份 `i′ = Java id + 1`。`ctr_ct <= ctr_sk` 的车辆尚未在加密时注册，必须拒绝。

例：已注册 5 辆时，latest 的 1/2/4/8 槽位层分别覆盖第 5 辆、第 3–4 辆、第 1–4 辆、空。第 1 辆到第 5 辆的解密路由依 MSB 选择包含自己的已完成块。第 6 辆之后加入，不获得访问此前密文的能力。

公钥、D1、D2、latest、注册计数器及任务完成状态以同一个 JSON 文件原子替换。失败的公钥校验不会推进 ctr 或留下半个注册结果。每个申请有 UUID；重复提交已完成任务可返回原身份。D 创建队列并授权角色，A/C 不能自行创建注册任务，B 无注册/注销权限。

## 与原项目结合时明确做出的扩展

### 1. 双向发送证明独立于接收块

在第 6 节中，不同层的最新完成块不一定包含发送者。直接对每个接收块调用原 `signcrypt(registry,sender,...)`，会把发送者错误地映射成另一个注册用户的局部槽位。

本实现拆成：

- 每个最新完成层的 C1–C4：保留原方案正向访问加密与转换公式。
- 一个发送证明 X1–X5：选取当前包含发送者的已完成块，使用发送者该层 q 生成。
- 挑战绑定 ctr、全局发送身份、访问矩阵、各层 C1/C2/C3、块 ID、AES nonce/payload。B 在转换时先做反向属性与发送证明验证。
- A 的指定密文撤销仍使用原 UK/PI 方程。若发送者不属于接收块，B 从 D 获取该发送者该层的注册公钥 Z 来验证 UK，不能误用该槽位其他车辆的 Z。

这是为将原双向方案接入第 6 节而做的工程适配，不是声称原论文逐行定义了该混合方案。C4 是授权更新字段，不放入不变挑战。原发送证明可塑性仍存在，见安全问题文档。

### 2. D 端注销

第 6 节只提供注册，**没有 Deregister 算法**。这里沿用用户原项目 `Scheme.deregister`：改变聚合 T/Q，并改变除目标槽位之外其他槽位的 V/R。

- D 将全局身份设为已注销，但不减 ctr、不复用编号。
- 对该身份所在的当前辅助块执行原 Deregister，生成新的不可变版本；更新相应 latest 和 D2 指针。
- 后续更大的层首次填满时，重新聚合其成员后，重新应用其中已注销成员的 Deregister，避免将其恢复。
- 加密使用更新后的块；离线代数测试验证目标旧私钥无法恢复新密文，其他车辆可以恢复。
- 在线 API 还拒绝已注销车辆的发送/解密请求，并在 C 释放明文前再检查一次状态。
- 历史块保留，供其他有效车辆解密各自有权解密的旧消息；同一身份的层可能具有多个注销版本。这是对第 6 节原始 D2 的版本化扩展。

**边界：**新公钥不能收回已经获得的明文，也不能阻止持有旧密文、旧辅助项和旧私钥的离线用户恢复旧消息。在线拒绝、未来密文的代数撤销、旧副本的边界分别测试和说明。

### 3. 追踪

泄露样本是 C 复制的实际私钥标量，不是预先写好的“身份答案”。编译后每辆车有多层私钥；演示样本选取其第 0 层 r。B 遍历第 0 层原始注册块匹配公钥，再执行原 Trace 的聚合、O/K、E/槽位方程，最后将局部槽位映射到全局注册身份。Trace 不信任样本中的 source 字段作为答案。原始块被保留，因此注销后仍能追踪原注册身份。

这演示的是有效完整车辆私钥副本中第 0 层标量的追踪，不是对任意黑盒解密器、任意不完整泄露或抗合谋追踪的证明。

### 4. 明文隔离

- `/api/state` 在任何端都不包含解密明文。
- C `/api/inbox?vehicle=id` 仅返回该本机用户车的记录；其他端/其他角色身份被拒绝。
- `inbox.json` 按 vehicle ID 分区保存；结果体包含实际 receiver。
- 前端切车立即清空结果和收件箱；请求序号、选择版本双重校验，旧请求不能回填新车辆界面。

每个 A/C 节点仍是一个可信实验操作者管理多辆模拟车辆；这不是给互不信任的真实终端用户建立独立登录账户。该操作者可以主动选择不同本机车辆。后台管理和明文接口只接受本机回环访问。

### 5. 同步运动

B 持久化运动 anchor/offset/paused。四端浏览器每秒通过本机后端读取 B 时钟，用请求往返时间作近似补偿，并依同一 vehicle ID 和同一轨迹函数计算位置。不依赖每台电脑的本地日期、页面启动时间或逐帧累计时长。

- 暂停/继续由 B 统一执行；D 只有查看权限。
- 页签短暂挂起后恢复会根据统一时间追上。
- 时钟断连超过 5 秒时停止外推并显示等待同步，恢复后重新对齐。
- 同一仿真时刻的世界坐标完全一致；实际运动显示仍受网络延迟、浏览器帧率和时钟补偿误差影响，不宣称各屏幕像素在物理时间上绝对无延迟。

## 数据与权限

A/C 本机密钥不上传普通注册流程。D 持有公共 CRS、各车公钥及注册辅助项；B 持有公共参数、密文、转换/撤销状态，以及用户明确创建的泄露测试样本。

四端采用独立角色令牌连接实验局域网；D 的本地注册/注销另受本机 API 和 CSRF 校验约束。此 HTTP 演示协议用于可信实验网络，未实现生产 PKI、恶意节点模型下的分布式共识或密钥硬件隔离。
