DEMO GUIDE

一座城市，四个端点。

先启动 D（Key Curator）和 B，再启动 A/C。可在一台电脑运行四端，也可部署到同一局域网中的四台电脑。

  1. D · 注册/注销填写车辆角色及属性，提交注册，等待对应 A/C 端生成密钥。选中已注册车辆可执行注销。
  2. A · 拥有者选择拥有者车辆，输入文字与接收策略，发送密文。
  3. C · 数据用户选择用户车辆、云端密文及发送方验证策略，完成本地解密。
  4. A · 动态撤销选中目标车辆与密文，授权更新；随后在 C 再次尝试。
  5. C → B · 追踪在 C 复制泄露样本，点击追踪，查看原算法识别的身份号。

车内视角在 A 或 C 点击本端车辆，或点击车辆卡片的“进入车内”，会打开唯一的车内窗口；车辆移动时窗口跟随，点击“跟随中”可暂停跟随，拖动地图后可用“继续跟随”恢复，按 Esc 或 × 关闭。车机屏显示导航地图和数据共享链路，发送、选择密文和解密仍在右侧浮窗完成。

地图运动使用 B 统一时钟；暂停对 A/B/C 同时生效。车辆身份和操作结果来自真实 Java 后端。第一次初始化和批量注册需要等待；重启会使用已保存的数据。旧密文副本不受新版本撤销追溯影响。

注册采用 Hohenberger 等第 6 节分层结构；双向验证、注销和文字封装属于结合原方案的工程扩展。已知发送方认证伪造问题详见项目 docs/SECURITY_FINDINGS.md。
